# Дорожная карта

Оценки — ориентиры из плана; после этапа 1 пересчитываются.

## Этап 1. Доказать запуск Gothic II на телефоне (1–2 недели)

- [x] Цель: лицензионное Gold-издание, варианты «Ночь Ворона» и классическая игра; отчёт о сборке в приложении.
- [x] Получить отчёт о сборке с копии игрока; заполнить `supported_builds.ini` (SHA-256 EXE, архивы, язык — русский).
- [x] Определить по отчёту, как Gold запускает классическую игру: `Gothic2c.exe` без аргументов, архивы аддона
  прячутся на время игры (`rename=`, `VariantLayout`); сохранения — в `Saves_GII` (по `Paths_GII.d`).
- [ ] Запустить на телефоне пользователя — теперь прямо из приложения (Winlator 11.2 встроен), без
  отдельной настройки Winlator: установить APK → «Играть» → прислать журнал, если не запустилось.
- [ ] Сравнить WoW64+Box64 и Box86+x86 Wine (запуск, мир, сохранения, звук, артефакты, задержка, час игры).
- [ ] Сравнить WineD3D и D3D7→D3D9→DXVK по сценам из TEST_PLAN.md.
- [ ] Подтвердить `KeyBindings`, ключи `GothicIniWriter.Keys`, способ доставки ввода (с `Gothic.ini` сборки
  уже сверены, осталось проверить в игре).
- [ ] Заполнить `runtime_components.ini` версиями и SHA-256; `DeviceProfile.verified=true` для прошедших.

**Критерий:** 30–60 минут игры — разговоры, бой, инвентарь, город, сохранение и повторная загрузка.
**Стоп-условие:** работает только «Ночь Ворона», а классический вариант нет — этап не завершён для классики
(вариант остаётся скрытым, Gold с «Ночью Ворона» можно выпускать отдельно).

## Этап 2. Отдельное приложение (2–4 недели)

- [x] Импорт через SAF, проверка по SHA-256, атомарное копирование, восстановление после сбоя.
- [x] Прямой запуск без экранов выбора; собственные сообщения об ошибках.
- [x] Жизненный цикл: фокус, пауза, аудиофокус, «Назад» = игровое меню.
- [x] Профили устройств и запись GOTHIC.INI/dxvk.conf до запуска.
- [x] Установщик компонентов: безопасная распаковка tar (пути, ссылки, биты исполнения), проверка SHA-256, атомарная установка, идемпотентность.
- [x] Локальный сокет моста в приватном каталоге, токен и путь передаются адаптеру через окружение.
- [x] Вывод без растягивания (теперь масштабирует X-сервер Winlator с сохранением пропорций).
- [x] Экран восстановления после выгрузки процесса или сбоя; отметка сеанса с heartbeat.
- [x] Предупреждение о перегреве без смены разрешения на ходу.
- [x] Среда исполнения — Winlator 11.2 модулем `:winlator` (замена пути rootfs, свой экран игры поверх
      `XServerDisplayActivity`, установка Wine без экранов Winlator, журнал Wine в диагностике).
- [x] Распаковка `.tzst` — средствами Winlator (zstd-jni).
- [ ] (после этапа 1) Импорт прямо из офлайн-установщика GOG (`setup_*.exe` + `.bin`), без ПК и Termux:
      встроить распаковку Inno Setup (например, innoextract, лицензия zlib) через NDK.
- [ ] Упаковка компонентов, проверка 16 КБ страниц, SELinux, запуск процессов без root.

**Критерий:** чистая установка → импорт → игра; следующие запуски без технических экранов.

## Этап 3. Полный сенсорный прототип (2–4 недели)

- [x] Джойстик с гистерезисом, относительная камера, кнопки, панели режимов, раскладка для левши.
- [x] Управление без ручных режимов: главная кнопка со свайпами, одна кнопка Esc, оружие с колесом
  слотов, панель подстраивается по клавишам приложения (2026-10-15). Проверить на телефоне.
- [x] Направленные удары, блок, единый арбитр, отсутствие залипаний (модульные тесты).
- [x] Геймпад через тот же арбитр.
- [ ] Подбор `CombatTiming` на 30 и 60 FPS на реальной игре.
- [x] Редактор положения кнопок в игре: перетаскивание с проверкой перекрытий во всех режимах, сброс.
- [x] Радиальное меню быстрых слотов и кнопка «последний слот»; с адаптером — типы содержимого слотов.
- [x] Замер задержки «касание → доставка события» (p50/p95 в журнале и на экране заглушки).
- [x] Геймпад скрывает сенсорную панель; касание возвращает её. Вибрация при нажатии.

**Критерий:** тестировщик проходит начальные задачи без клавиатуры, мыши и геймпада.

## Этап 4. Контекстный адаптер (3–6 недель, высокий риск)

- [x] Протокол, рукопожатие с токеном и SHA-256 EXE, таймаут, fallback на ручные панели.
- [ ] Адаптер внутри процесса Gothic II для закреплённого EXE (C++), локальный сокет.
- [ ] Быстрые слоты с реальными иконками, события завершения сохранения → `SaveBackupPolicy`.

**Критерий:** панели соответствуют реальному состоянию и не отправляют опасные команды в неправильное меню.
Если адаптер окажется слишком сложным — выпуск с ручными режимами, без эвристик.

## Этап 5. Стабилизация (3–5 недель)

Несколько устройств, длительные сессии, нагрев, звук, сворачивание, восстановление,
импорт/экспорт, обновление приложения без потери данных.

## Этап 6. Полное прохождение и выпуск

Полное прохождение закреплённой конфигурации, все миры и ролики, сохранения между главами,
повторная проверка после фиксации финальной среды. Закрытая подписанная APK-бета.

## Условия готовности

- Поддерживаемая сборка определяется автоматически, неподдерживаемая отклоняется понятным сообщением.
- Ни один обычный запуск не показывает рабочий стол или технический лаунчер; без root.
- Играется двумя большими пальцами; движение не превращается в атаку; блок не залипает.
- Диалоги, торговля, замки и все сюжетные действия доступны без клавиатуры.
- Прогресс сохраняется между главами; копии не делаются из недописанных файлов; обновление не теряет данные.
- Пройдены полное прохождение, длительные тесты после прогрева, звонки, блокировка, сворачивание.
- Опубликован список проверенных устройств и сборок; производительность — по измерениям.
